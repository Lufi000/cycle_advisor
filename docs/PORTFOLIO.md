# Cycle Advisor

### 用周期数据理解自己，而不只是记录它

---

## 我想用逻辑解释自己的情绪

有一段时间，我发现自己在经期前后情绪会很低落，也更容易跟伴侣吵架。我知道这跟激素有关，但知道归知道——在那个情绪里，我没有办法让自己平静下来，因为我没有证据，只有感受。

我当时在用 Apple 健康的周期功能。它给了我很多数据，但我看不懂这些数据意味着什么。更让我挫败的是，我很想把周期数据跟 HRV、运动时长、睡眠、体重放在一起看，但没有任何一个工具允许我这样做。

我想做的东西很简单：一个真正了解我身体的 AI，能告诉我「你现在的状态是这样，可能是因为这个，你可以试试那个」。

---

## 市场与机会

### 赛道在增长，但有一个明显的空白

全球女性健康 App 市场正以每年约 17–20% 的速度增长。中国占全球约 20% 的份额，是仅次于北美的第二大市场。经期健康是其中规模最大的细分领域。

主要玩家有国内的美柚、大姨妈，国际的 Flo、Clue——它们的共同定位是**记录工具**：帮你记下经期、预测排卵、提醒下次月经。

但记录之后呢？

数据存在手机里，用户还是不知道这些数据意味着什么，也不知道应该怎么做。这是现有产品普遍没有解决的问题——**从「记录」到「理解自己」，中间有一个巨大的断层。**

### 这个产品的位置

Cycle Advisor 不做记录，数据由 Apple HealthKit 直接提供。它想解决的是记录之后的那个问题：**帮用户读懂这些数据，给出可以真正落地的生活方式建议。**

加上二十四节气这条线，是在做一个全球竞品没有、也不太可能去做的方向——把西方健康数据和东方生活智慧放在同一个产品里，面向认同「顺应自然节律生活」这套逻辑的中文用户。

## 用户：软性需求，不是刚需

用户研究主要来自我自己，以及和一个朋友的对话——没有做正式访谈，这是这个项目的局限之一。

目标用户是想了解自己情绪和身体节律、愿意根据数据调整生活方式的人。我主动排除了备孕用户和有就医需求的用户。他们需要的是精准；我想做的是洞察。

这类需求比较软性，不如「预测排卵期」那么刚需，但它是我自己真实的需求。

## 产品策略

### 三个有意识的取舍

**选了生活建议，没做健康评分。**
不想给用户贴「异常」标签，不想制造焦虑。这既是 App Store 的合规要求，也是我自己不认同那个方向——我想要的是陪伴和引导，不是诊断。

**加了二十四节气养生建议。**
不是为了跟竞品差异化，是因为读了一本中医启蒙书，认同「人应该顺应节气去生活」这个逻辑。产品里的建议不只来自 HealthKit 数据，也来自节气时令——这两条线在界面里交汇。

**伴侣共享功能推后了。**
我最初做这个项目，部分动机就是想减少跟伴侣的争吵。理想状态是：当我处于容易情绪急躁的周期阶段，伴侣收到一个提醒，知道「这不是她对你有意见，是激素的影响」。但这个功能涉及隐私边界，没想清楚之前不想动手。

### 为什么不直接用 ChatGPT？

用户会问：「我直接问 ChatGPT 不行吗？」

可以，但你每次都要先解释自己——「我现在经期第三天，最近睡眠不好，HRV 偏低……」。这不只是麻烦，更重要的是：当你情绪低落的时候，你往往说不清楚自己的状态，也不知道该问什么。

小芽的差异在于：**她不需要你解释，因为她已经读过你的数据。** 打开对话，她就在你的上下文里，知道你昨晚睡了多久、今天是周期第几天、现在是什么节气。这个上下文不是你告诉她的，是 HealthKit 给的。

## 设计语言

### 产品判断决定了视觉方向

选了陪伴而不是诊断，界面就不能是冷色系的仪表盘。选了节气养生，视觉语言就需要能承载东方的自然意象。选了不做警告和评分，整套配色就不能有任何红色和橙色。

所以这是一个反直觉的设计问题：**一个数据产品，为什么要长得像植物手帐？**

按照惯例，健康数据产品应该长什么样？Apple Health 的白底蓝绿，Clue 的深色数据卡——因为它们要传递「精准」和「可信」。我选了反方向：暖奶油色底，牡丹花 logo，低饱和度的自然色系。

**用户打开这个 App 的时机，往往是情绪低落、不知道自己为什么烦躁的时候。这个时刻，一个看起来像医疗设备的界面会加重焦虑，而不是缓解它。** 视觉语言必须传递的信号是：「我了解你，没关系。」

### 色彩：四季与四个周期相位

经期、卵泡期、排卵期、黄体期——四个相位需要在视觉上可区分，但不能像红绿灯一样制造高低判断。每种颜色都是自然界里真实存在的颜色：

```
经期     → 柔粉   #E98AB8   山茶花
卵泡期   → 草绿   #76AB4A   鼠尾草
排卵期   → 暖黄   #D7D04B   向日葵
黄体期   → 莫兰迪紫  #A8659F  薰衣草
```

同一套颜色也映射到节气卡片上：春绿、夏黄、秋粉、冬紫。当用户在主页同时看到「当前是春分」和「当前处于卵泡期」，这两张卡片在颜色上是和谐的——潜意识里会觉得：自然节律和身体节律是同一件事。

**颜色约束只有一条：禁止红色、橙色、或任何警告色系。** 不是技术约束，是产品价值观——这个 App 不发警报。

### 组件：每一个都有被砍掉的功能

**周期环**是主页最重要的元素。设计它时做了一个取舍：环上没有任何标注文字。最初版本在每个色段上标了相位名称，看起来更「信息丰富」，但用户的视线会分散到数据本身，而不是感受「我现在处于哪个阶段」这件事。

最终版本阅读路径更自然：看环 → 感知相位 → 看中心 → 确认名称 → 看下方 → 读建议。

**底部导航只有两个 Tab：小花园（主页数据）和 AI 助手（对话）。** 这是产品决策，不是没做完。核心使用路径只有两种，其他功能通过汉堡菜单进入。导航越简单，用户打开 App 时的决策成本越低——这在一个情绪低落时会用到的产品里，尤其重要。

### 语气：最容易被忽略的设计决策

界面文案的语气是设计的一部分，但经常被当成最后填内容的地方来处理。这个产品定了一张明确的词汇对照表：


| 允许          | 禁止       |
| ----------- | -------- |
| 身体处于恢复期     | 检测到异常    |
| 可以试试适当散步    | 你必须减少运动  |
| 这个阶段通常会感到疲惫 | 你的疲劳指数偏高 |
| 暂时没有足够数据    | 数据错误     |


禁止的不只是某些词，是一种说话方式——不能让用户觉得自己被一个系统评判，要让用户觉得自己被一个朋友理解。

## AI 助手：小芽

### 设计出发点

这个 App 里最难设计的部分不是界面，是 AI 助手的交互方式。

大多数 AI 助手的默认模式是：用户提问，AI 回答。但这个产品的用户打开对话的时机，往往不是「我有一个问题要问」，而是「我今天感觉不太对，但说不清楚」。这种状态下，让用户先开口是一种负担。

所以小芽的设计是：**她先说话。**

### 第一句话的设计

每次打开对话，小芽已经读取了用户当天的健康数据——周期阶段、HRV、睡眠质量、运动记录、当前节气。她用这些数据主动开口，而不是等用户解释自己的状态。

她说的话做三件事：告知当前状态、提供合理化解释（不是情绪出了问题，是激素）、给出一个可执行的小建议。这三件事的顺序是刻意设计的——**先被理解，再被建议。**

### 人设约束

小芽的人设是：**了解你身体的朋友，不是医生，不是教练。**

- **不评判**：不说「你今天运动量不足」，说「今天身体可能需要多一点休息」
- **不断定**：不说「你的 HRV 偏低说明压力过大」，说「HRV 这两天稍微低一些，可能和睡眠有关，不用担心」

## 用下来发现的事

App 在真机跑通后，我自己用了一段时间。发现了一个问题：身体数据和周期之间的关联，AI 很难分析得准确有用，建议有时候感觉泛泛，不够落地。

但也发现了一件意外的事：正是因为小芽「知道」我的周期阶段、知道我最近的睡眠和运动状态，她说出来的话有一种被理解的感觉。建议不一定实用，但那种「有人懂我在经历什么」的感觉是真实的。

这让我意识到，**陪伴感的来源不是 AI 有多聪明，而是它拥有足够的上下文。** 小芽之所以让人感觉被理解，不是因为她的回答有多精准，而是因为她开口之前已经知道你昨晚没睡好、今天是经期第几天、窗外是什么节气。

## 商业模式与增长

### 商业模式

当前专注一条线：**对话订阅。**

基础功能免费——周期数据、节气建议、HealthKit 摘要。付费会员解锁更多和小芽的对话次数。每次对话消耗 token，这个成本是真实的，免费用量有上限是合理的边界。

愿意付费的用户，是真正在用小芽处理情绪和寻求陪伴的人——付费行为本身就是粘性的证明。

后续可能探索的方向：与健康平台合作、高级功能解锁、周期健康洞察报告。但这些在验证核心产品价值之前不会提前做。v1 不设付费，目标是先跑通产品方向和 App Store 审核路径。

### 增长路径

**Widget 是第一个传播入口。** HealthKit 数据做成桌面小组件，用户把周期环、当日节气、健康摘要放在手机主屏幕——这本身就是每天可见的触点，也是最自然的分享场景。朋友看到问一句「这是什么 App」，就完成了一次传播。

**小红书是核心分发渠道。** 目标用户高度聚集在小红书，「经期情绪」「身体节律」「中医养生」都是高活跃话题。用户故事比产品介绍更有传播力。

**社群活动作为留存手段。** 组织用户分享经历和身体故事，既能产生内容，也能建立用户之间的连接感。这个方向还在规划中。

---

## 现状与反思

真机跑通，还在迭代。目前花时间最多、也最想继续打磨的是 AI 助手对话体验。

UI 设计那部分，花了很多 token 在反复改小细节，效果还不好。如果重来，会先确定好设计规则，再让 AI 去做，而不是一边摸索一边修改。

---

## 这个产品想留下的那句话

有一次身体不舒服，打开小芽说了一句「今天感觉不太好」。她回的话没有特别精准，建议也不算多有用，但她是在知道我的数据的前提下说的——她知道我今天是周期第几天，知道我最近睡得怎么样。

那一刻有一种说不清楚的感觉，就是——**它好像是一个真正了解我的人。**

这是这个产品最想做到的事，也是它目前最接近做到的事。
