# 产品决策纪要

本文档落实主方案第九节「需要先确认的问题」，并与仓库内实现保持一致。**若修订决策，请同步更新本文档与 [MVP_TECH.md](./MVP_TECH.md)。**

## MVP 形态（已锁定）

- **v0.1 主路径：形式 B — iOS App（HealthKit 直读）**（明确选用 B；与主方案第六节「先 Web 验证」的推荐路径不同，属有意识取舍。）  
- 不依赖用户手动导出 `export.xml`；通过系统 HealthKit 授权读取数据后，在 App 内生成生活向建议。  
- **分析范围**：经期相关含「健康」中可选的周期补充类别（如不规律/稀发/延长等，见 [MVP_TECH.md](./MVP_TECH.md) §1.1）；另含生活与周期上下文类型（睡眠手腕温度、活动、睡眠、心率与 HRV、锻炼、饮食与饮水、正念，及可选体成分等，见 §1.2）。均仅输出**结构化摘要**再进入建议链路。仍**不**做独立 watchOS App。

## 第九节五条 — 当前结论

### 1. 目标用户

- **假设（可修订）**：已在「健康」或兼容 App 中积累经期及相关生活方式数据的用户；希望基于现有数据获得**非医疗**的生活建议（饮食、运动、情绪等），而非迁移到另一套记账体系。

### 2. 隐私策略

- **HealthKit**：仅通过系统界面请求权限；在 App 内说明读取的数据类型与用途（与隐私政策、App Store 声明一致）。遵守 Apple 对健康数据的使用限制（见 `.cursor/rules/appstore-health-compliance.mdc`）。
- **与 AI 的边界（假设，可修订）**：默认将**结构化摘要**（如周期长度范围、记录天数、流量与周期补充类别统计，以及活动/睡眠/心率/手腕温度、锻炼/饮食饮水/正念、可选体成分等**聚合指标**）发往模型 API；**不**将可逆识别个人的原始样本批量明文用于与第三方共享。**若改为纯端侧模型**，需在 [MVP_TECH.md](./MVP_TECH.md) 中改写数据流。

### 3. 商业化

- **假设（可修订）**：v0.1 为验证与审核路径，**不设付费、无订阅**；后续是否商业化单独立项。

### 4. 差异化与交互（健康分 / 异常标签）

- **假设（可修订）**：v0.1 **不采用**「健康打分」「异常」红标等强判断式表达；以**温和、可执行的生活建议清单**为主，降低审核与用户焦虑风险（与主方案 5.4 一致）。

### 5. 仓库与协作

- 本地根目录：`cycle_advisor`。Git 初始化见 [SETUP.md](./SETUP.md)；远程仓库由维护者自行在 GitHub/GitLab 创建后关联。
