# CycleAdvisor 怀孕预测功能设计

日期：2026-09-04
状态：待评审

## 背景与目标

为 CycleAdvisor 增加"怀孕可能提示"功能。目标用户是**正在备孕**的用户。

**整体设计原则**：以手表自动采集的健康数据为主信号——**手腕温度**（排卵定位与高温相监测）、**静息心率（RHR）**、**HRV**（早孕自主神经变化的佐证信号），融合**经期数据**（推迟天数）与**症状**（HealthKit / 手动打卡 / AI 助手对话抽取）进行多信号判定。手表数据经 HealthKit 自动汇总到 iPhone（与已定稿的 Watch spec 一致，不依赖 WatchConnectivity），**手动基础体温（BBT）录入仅作为无手表用户的兜底路径**。

核心原则：**功能只做"提示验孕"，永不宣称"已怀孕"**。确诊只能通过 hCG 检测。

## 总体架构（方案 A）

判定逻辑全部在 App 本地（确定性规则引擎，可单测、可解释、隐私好）；LLM 仅用于从聊天消息中抽取结构化症状标签，走 BFF 独立端点，不侵入主聊天链路。

```
Apple Watch ──▶ HealthKit：腕温 / RHR / HRV ──┐
用户晨起测温 ──手动录入──▶ 体温库（兜底） ──────┤
HealthKit 症状 / 手动打卡 ──▶ 症状库 ──────────┼─▶ PregnancyInsightEngine ──▶ 提示等级 ──▶ UI 提示卡
聊天消息 ──异步──▶ BFF /v1/extract/symptoms ──┤        ▲
                      (deepseek-chat, JSON)   │        │
经期记录（HealthKit menstrualFlow）───────────┴────────┘
```

## 模块 1：数据模型与存储

### BasalTemperatureEntry

| 字段 | 类型 | 说明 |
|---|---|---|
| date | Date（日粒度） | 测量日，同一日只保留一条（后录入覆盖） |
| celsius | Double | 基础体温，合法范围 35.0–38.0，超出拒绝录入 |
| disturbances | Set<Disturbance> | 干扰标记：熬夜 / 饮酒 / 生病 / 失眠（仅手动录入可标记） |
| source | enum | wristTemperature（手表自动）/ manual（手动兜底） |

- 有干扰标记的条目参与绘图，但在排卵定位中降权（见模块 3）
- **来源优先级**：同日同时存在手表与手动记录时，以 wristTemperature 为准（手表夜间多次采样取均值，稳定性优于单次口温）
- 手表来源：HealthKit `appleSleepingWristTemperature`（Series 8+/Ultra，需佩戴睡眠约 2 周建立基线；样本本身就是摄氏度绝对值，直接入序列）。腕温绝对值比口温高约 1°C，但 3-over-6 看的是**相对位移**，阈值通用

### DailyVitals（手表每日生命体征）

| 字段 | 类型 | 说明 |
|---|---|---|
| date | Date（日粒度） | |
| restingHeartRate | Double? | bpm，HealthKit `restingHeartRate` 当日均值 |
| hrvSDNN | Double? | ms，HealthKit `heartRateVariabilitySDNN` 当日均值 |

- 引擎内部维护两个个人基线：卵泡期 RHR 均值、卵泡期 HRV 均值（每周期前 7 天滚动更新），佐证判定全部相对个人基线，不设绝对阈值

### SymptomRecord（统一症状库）

| 字段 | 类型 | 说明 |
|---|---|---|
| date | Date | 症状发生日 |
| type | SymptomType | 见下方枚举 |
| source | enum | healthKit / manual / chatExtracted |

- 去重键：(date, type)，同日同症状只保留一条，优先级 manual > healthKit > chatExtracted
- SymptomType 枚举（映射 HealthKit 类别）：nausea、vomiting、fatigue、breastTenderness、bloating、abdominalCramps、headache、spotting、appetiteChange、moodChange、dizziness

### 存储策略

- **本地为主**：手动 BBT 与症状库各自存为 Documents 目录下的 JSON 文件（与 UserProfileManager 相同的持久化模式），HealthKit 写入为可选同步
- **手表数据不落本地**：腕温 / RHR / HRV 以 HealthKit 为唯一数据源，每次判定时现读（HealthKitManager 新增三类日序列拉取），不做本地冗余存储
- HealthKit 授权被拒绝时纯本地运行，功能不阻塞；仅失去与其他 App 的数据互通
- 读取侧仍走 HealthKitManager 已有的 `fetchMenstrualSymptoms` 拉取系统症状并入症状库

## 模块 2：备孕模式开关

- `UserProfile` 新增 `isTryingToConceive: Bool`（默认 false）
- 设置/Profile 页加入口开关，附一句说明："开启后将基于你的健康数据追踪周期信号，并在合适时机提示验孕"
- 开关关闭时：不显示备孕卡片、不发测温提醒、不触发怀孕提示；已有数据保留

## 模块 3：判定引擎 PregnancyInsightEngine（本地纯逻辑）

输入：近 60 天体温序列（手表腕温优先，手动 BBT 兜底）、近 60 天 DailyVitals（RHR/HRV）、经期记录（HealthKit menstrual flow，复用现有周期预测得出预期经期日）、症状库。

输出：`PregnancyInsight` 枚举 —— `insufficient` / `tracking(lutealDay: Int)` / `possible(reasons: [Reason])` / `likely(reasons: [Reason])`。reasons 用于 UI 展示解释（如"体温持续高位 16 天""静息心率较基线上升 3 bpm"）。

### 信号分层

| 层 | 信号 | 作用 |
|---|---|---|
| 主信号 | 腕温 / 手动 BBT | 定位排卵、计算高温相天数——唯一能独立触发提示的信号 |
| 佐证信号 | RHR、HRV、早孕症状 | 不能独立触发提示，只用于提升档位、加强置信 |
| 基础信号 | 经期推迟天数 | 与主信号组合触发；无温度数据时的降级触发器 |

### 排卵定位（3-over-6 规则）

1. 取连续有效测温日序列（手表腕温全部有效；手动条目中无干扰标记的为"有效"，有干扰标记的仅在无替代时使用且该次判定降一级置信）
2. 某日起连续 3 天温度 ≥ 前 6 个有效日均值 + 0.2°C → 判定升温，**升温前最后一低温日为排卵日**
3. 数据不足 10 个有效日，或未检测到双相 → 无法定位排卵

### 佐证信号判定（全部相对个人卵泡期基线，不设绝对阈值）

- **RHR 升高**：月经预期日前 RHR 未回落，且高于卵泡期基线 ≥ 2 bpm 持续 ≥ 5 天（未孕周期中 RHR 在经前回落，怀孕则持续爬升）
- **HRV 抑制**：HRV 低于卵泡期基线 ≥ 10% 持续 ≥ 5 天（早孕自主神经改变，HRV 趋势性下降且经前不回升）
- **早孕症状 ≥ 2 项**：恶心/呕吐/疲倦/乳房胀痛/点滴出血（当周期去重后计数）

### 提示等级规则

| 等级 | 条件（任一满足） | UI 动作 |
|---|---|---|
| tracking | 已定位排卵，高温相 < 12 天 | 显示"黄体期第 X 天"，不提示验孕 |
| possible | 高温相 ≥ 12 天且月经未至；或已定位排卵且经期推迟 1–3 天且佐证信号 ≥ 1 | 温和提示："现在可以用验孕棒检测了" |
| likely | 高温相 ≥ 16 天；或高温相 ≥ 14 天且佐证信号 ≥ 2 | 较强提示："建议尽快验孕确认" |

**likely 必须有温度主信号（腕温或手动 BBT 皆可）**——是否触发强提示取决于"有没有温度数据"，而非手表型号。Series 7 等无腕温手表的用户只要坚持手动录入 BBT，就走完整规则阶梯，且 RHR/HRV 佐证由手表自动采集；完全无温度数据的用户才走降级路径，永不触发强提示。

降级路径（完全无温度数据——既无腕温也未手动录入，无法定位排卵）：仅按"推迟 ≥ 3 天且佐证信号 ≥ 2"判定，只出 possible 一档，措辞更保守。

### 用户反馈闭环

提示卡附"记录验孕结果"：阳性 / 阴性 / 忽略。
- 阳性：停止提示，引导用户更新状态（本期只做记录与提示语变更，不做完整孕期模式）
- 阴性：本周期内不再提示；新周期（检测到新经期开始）后重置
- 忽略：7 天内不重复提示

## 模块 4：聊天症状抽取（BFF + LLM）

### BFF 新端点 `POST /v1/extract/symptoms`

- 鉴权、限流复用现有 proxy 机制
- 请求体：`{ "message": "<用户单条消息>", "language": "<locale>" }`
- BFF 转发 deepseek-chat，固定 system prompt 要求抽取症状，`temperature: 0`，`response_format: { type: "json_object" }`，`max_tokens: 300`
- 响应：`{ "symptoms": [{ "type": "nausea", "date_ref": "today" | "yesterday" | null }] }`，BFF 解析校验后透传；解析失败返回空数组

### App 侧 SymptomExtractor

- 时机：用户在 AI 助手发出消息后异步触发，只抽取**用户消息**，不抽取助手回复
- 客户端节流：消息长度 < 4 字跳过；同日已抽取过的消息不重复请求
- 失败静默，不影响聊天主链路，不重试（下条消息自然带来新机会）
- 抽取结果以 source = chatExtracted 写入症状库（参与去重）

**明确不做**：不把抽取塞进主聊天 prompt——会污染回复格式、增加主链路延迟和 max_tokens 压力。

## 模块 5：UI 与通知

- **首页备孕卡片**（仅备孕模式可见）：黄体期第 X 天 / 提示等级、体温近 14 天趋势迷你图、佐证信号状态（RHR/HRV 趋势图标，无手表时隐藏）
- **手动 BBT 录入页**（无手表用户的主路径）：数字输入（一位小数）、干扰标记多选、"今早已测"状态；检测到手表现有腕温数据时弱化入口，改为"手动补录"
- **晨间提醒**：仅对无手表数据覆盖的用户发本地通知，用户可设时间（默认 7:00），文案避免在锁屏暴露敏感信息（用"该测体温啦"而非"备孕提醒"）
- **提示卡**：possible / likely 两档文案 + 触发原因展示（reasons）+ "记录验孕结果"按钮 + 免责声明"此功能不构成医疗诊断"

## 模块 6：合规与本地化

- 所有文案只出现"可能怀孕 / 建议验孕确认"，永不出现"你已怀孕"
- 首次开启备孕模式时展示一次性免责说明
- 7 语言文案走现有 lproj 流程（zh-Hans、zh-Hant、en、ja、ko、es、fr）

## 模块 7：错误处理

| 场景 | 行为 |
|---|---|
| 温度数据不足（< 10 有效日） | insight = insufficient，UI 引导坚持测温（或佩戴手表睡眠），不出任何提示 |
| 手表基线未建立（佩戴 < 14 天） | 腕温数据暂不参与判定，引导用户先手动录入过渡 |
| 缺测日 | 序列中标记 gap；3-over-6 窗口内 > 2 个 gap 则该窗口跳过 |
| 干扰标记日 | 绘图保留，定位时降权 |
| RHR/HRV 数据缺失（无手表或权限拒绝） | 佐证层降级：只保留症状佐证，主信号判定不受影响 |
| 抽取端点失败/超时 | 静默丢弃，不影响聊天 |
| HK 授权拒绝 | 纯本地模式（手动 BBT + 手动症状），功能可用 |
| 用户关闭备孕模式 | 停止提醒与提示，数据保留 |

## 模块 8：测试

- **PregnancyInsightEngine 单测**（核心）：固定序列构造场景 —— 正常未孕周期（高温相 12 天回落）、怀孕周期（高温相 ≥ 18 天）、黄体期短（< 10 天不出提示）、大量缺测、干扰标记日、无温度数据降级路径、佐证信号组合升档（高温 14 天 + RHR 高 + 症状 ≥ 2 → likely）、RHR/HRV 相对个人基线的偏离判定、阴性反馈后本周期不再提示
- **SymptomExtractor 单测**：mock BFF 响应（正常 JSON / 空数组 / 畸形 JSON / 网络失败）
- **去重逻辑单测**：同日同症状多来源合并；同日手表腕温与手动 BBT 冲突时以手表为准
- **BFF Go 单测**：端点鉴权、限流、DeepSeek 响应解析失败兜底

## 准确率预期（产品预期管理）

此类方案无权威大样本验证数字，"高温 16–18 天"是临床经典经验法则。预估（前提是用户数据覆盖良好——手表自动采集或坚持每日手动测温）：

| 档位 | 触发后真怀孕占比（预估） | 主要误差来源 |
|---|---|---|
| possible | 20–40% | 周期本身波动、黄体期偶尔偏长、压力/生病导致推迟 |
| likely | 70–90%（手表用户数据完整，实际触发质量偏上限） | 生化妊娠（约 20–30% 受孕在着床后早期自然流失，体温先高后落）、黄体囊肿 |

另一半真相是漏报：真怀孕但测温断断续续的用户，可能到月经推迟数日仍在 tracking 状态。**功能定位是"在合适时机提醒验孕"而非诊断**——验孕棒在推迟 1 周后的准确率本身超过 97%，本功能的价值是引导用户在正确时间点使用高准确率手段。提升实际成功率的最有效手段是数据覆盖率（手表自动采集 / 晨间提醒），而非调阈值。

## 范围外（本期不做）

- 睡眠呼吸率、皮肤灌注等更多手表信号的接入（预留 DailyVitals 扩展位，未来可加）
- 完整孕期模式（阳性后的孕期追踪）
- 排卵预测窗口（本产品已有的周期预测不改动）
- 排卵试纸（LH）录入
