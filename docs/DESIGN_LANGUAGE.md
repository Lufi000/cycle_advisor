# Cycle Advisor 设计语言

## 一个数据产品，为什么要长得像植物手帐

---

## 设计起点：一个反直觉的选择

这是一款读取健康数据、结合 AI 给出建议的 iOS App。

按照惯例，这类产品应该长什么样？Apple Health 的白底蓝绿，Clue 的深色数据卡，或者某种充满仪表盘感的科技风界面——因为它们要传递「精准」和「可信」。

我选了一个反方向：暖奶油色底，牡丹花 logo，低饱和度的自然色系。

这个决定不是审美偏好，是产品判断。

**这个产品的核心价值不是分析，是陪伴。** 用户打开它的时机，往往是情绪低落、身体不舒服、不知道自己为什么烦躁的时候。这个时刻，一个看起来像医疗设备的界面会加重焦虑，而不是缓解它。视觉语言必须传递的信号是：「我了解你，没关系。」

所以这是一个草木疗愈系的设计——不是因为女性健康产品应该是粉色的，而是因为植物、自然、节气这套意象，和产品里真正在做的事情是对齐的。

---

## 色彩：四季与四个周期相位

配色方案围绕两个逻辑展开：**周期相位**和**自然季节**。

### 周期相位的颜色

经期、卵泡期、排卵期、黄体期——四个相位需要在视觉上可区分，但不能像红绿灯一样制造高低判断。我选择了四种颜色，每种都是自然界里真实存在的颜色：

```
经期     → 柔粉   #E98AB8   山茶花
卵泡期   → 草绿   #76AB4A   鼠尾草
排卵期   → 暖黄   #D7D04B   向日葵
黄体期   → 莫兰迪紫  #A8659F  薰衣草
```

这四个颜色在周期环上构成一个完整的圆，颜色本身没有好坏之分——它们只是不同的季节。

### 底色的决定

全局底色是 `#F9F0E9`，一个带着微微粉感的奶油白，而不是纯白。

纯白在 iOS 上会让界面显得过于临床。这个底色会让整个界面像一张质感好的纸，卡片放上去有托住的感觉，品牌色放上去是柔和的而不是刺眼的。

### 约束

- 所有颜色饱和度控制在 60% 以下
- 禁止使用红色、橙色、或任何警告色系——不是技术约束，是产品价值观：这个 App 不发警报

## 字体：不能让界面显得像说明书

字体系统只有一个原则：**让人觉得是在被告知一件事，而不是在阅读一份报告。**

系统字体 SF Pro + PingFang SC，不引入自定义字体。不是因为懒，是因为：用户对系统字体有信任感，在一个健康类产品里，可信比个性更重要。

定义了五个字阶，每个字阶只对应一种使用场景：


| 字阶      | 字号            | 场景            |
| ------- | ------------- | ------------- |
| Display | 28pt Bold     | 节气名称、唯一的页面大标题 |
| Title   | 20pt Semibold | 卡片标题          |
| Body    | 15pt Regular  | 所有建议内容、描述     |
| Label   | 13pt Medium   | 数据标签、Tab 文字   |
| Caption | 11pt Regular  | 辅助信息、倒计时      |


**关键约束：一个页面不能同时出现超过三个字阶。** 字阶越多，信息层级越模糊，用户越容易不知道先看哪里。

## 组件：每一个都有被砍掉的功能

### 周期环：视觉焦点，不是数据图表

周期环是主页最重要的元素。它是一个环形图，四色分段，对应四个相位。

设计它的时候做了一个取舍：**环上没有任何标注文字。**

最初的版本在每个色段上标了相位名称，看起来更「信息丰富」，但测试下来感觉很拥挤，而且会让用户的视线分散到数据本身，而不是感受「我现在处于哪个阶段」这件事。

最终版本环上只有颜色，文字全部放到环的中心和正下方。信息量没少，但阅读路径变得更自然：看环 → 感知相位 → 看中心 → 确认名称 → 看下方 → 读建议。

### 节气卡片：东方语境的锚点

App 里有一块二十四节气的内容，这在竞品里几乎没有。

节气卡片的设计目标是：**让它看起来是这个 App 的一部分，而不是一个突兀的模块。**

解法是让节气卡片和周期使用同一套颜色逻辑——春绿、夏黄、秋粉、冬紫，跟周期相位色调相互呼应。当用户在主页同时看到「当前是春分」和「当前处于卵泡期」时，这两张卡片在颜色上是和谐的，潜意识里会觉得：自然节律和身体节律是同一件事。

### 底部导航：只有两个 Tab，不是妥协

很多 App 到后期会把导航塞满，五个 Tab，甚至用 Tabbar + 汉堡菜单混用。

这个 App 的导航只有两个入口：**小花园**（主页数据）和 **AI 助手**（对话）。

这是产品决策，不是没做完。这个 App 的核心使用路径只有两种：「查看当前状态」和「和 AI 说话」。所有其他功能（设置、历史记录、隐私说明）通过左上角的汉堡菜单进入。

导航越简单，用户打开 App 时的决策成本越低——这在一个情绪低落时会用到的产品里，尤其重要。

---

## 语气：最容易被忽略的设计决策

界面文案的语气是设计的一部分，但经常被当成最后填内容的地方来处理。

这个产品定了一张明确的词汇对照表：


| 允许          | 禁止       |
| ----------- | -------- |
| 身体处于恢复期     | 检测到异常    |
| 可以试试适当散步    | 你必须减少运动  |
| 这个阶段通常会感到疲惫 | 你的疲劳指数偏高 |
| 暂时没有足够数据    | 数据错误     |


**禁止的不只是某些词，是一种说话方式**——不能让用户觉得自己被一个系统评判，要让用户觉得自己被一个朋友理解。

---

## 这套设计系统在解决什么问题

一个核心矛盾：**这个 App 需要展示数据，但不能让人感觉在看数据。**

用户来这里不是为了分析 HRV 数字，而是为了理解自己。设计的工作是让数据退到背景里，让「状态感知」和「被理解的感觉」走到前台。

暖色底让界面不冷，植物意象让健康数据不像医疗报告，语气约束让 AI 对话不像说教，节气卡片让产品有了时间感和文化锚点——这些不是孤立的视觉决策，它们共同服务于同一件事：让用户打开 App 的那一刻，感觉是在被照顾，而不是被检查。
